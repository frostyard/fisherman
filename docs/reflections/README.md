# Engineering reflections

This directory preserves short, non-secret lessons that should survive an
individual development session. Add a dated Markdown file after an escaped
defect, revert, repeated review finding, flaky required gate, or meaningful
process correction.

Each reflection should record the observed signal, root cause, durable change,
verification, and any follow-up issue. Do not include credentials, private
incident details, unredacted logs, personal data, or speculative blame. Current
code, tests, workflows, and issue decisions remain authoritative; update or
supersede a reflection when its advice becomes stale.

Use this template:

```markdown
# YYYY-MM-DD — Short title

## Signal

## Root cause

## Durable change

## Verification

## Follow-up
```
